THE DESIGN TRADE-OFF

Parquet compatibility.
Page-level mutability.

Not a new query engine. A different way to store and expose a table.

01

Copy-on-write, below the file

Updating revenue_cents for order 8 rewrites just its revenue page. Deleting order 2 rewrites its seven column pages. Unchanged page IDs are reused.

02

History is a reference graph

Snapshots use segment visibility bounds [added_in, removed_in). Old page bytes remain readable. Rename, reorder, and drop use stable column IDs: metadata-only changes.

03

One portable storage unit

One table per SQLite file. Page blobs and metadata commit atomically in a transaction. WAL supports several readers and one writer. Copy with no active writer, or use SQLite backup.

04

Small appends, buffered

Orders 12 and 13 are immediately visible as a compact columnar batch. Reads synthesize and cache Parquet pages; flush stores them. Auto mode directly encodes batches of 65,536 rows or more.

05

Statistics can prune safely

VPF recomputes page bounds from decoded values. DuckDB can push supported comparisons, NULL checks, BETWEEN, AND, and OR into candidate-range pruning. It still applies exact filters; unsupported OR branches stay unpruned.

06

Ordinary readers, three paths

Use Rust’s ChunkReader, HTTP byte ranges, or a read-only FUSE mount. Export a standalone Parquet file when needed. Nested columns map to one chunk per leaf.

LATEST: CHOOSE WHEN SNAPSHOT LAYOUTS ARE PREPARED

Lazy is the default. Eager shifts work to writes.

Lazy

Resolve virtual layout on demand. Appends avoid loading existing row groups, page metadata, and buffered payloads. The C API caches one resolved snapshot per handle.

Eager

Persist the footer and offset map atomically with each write. Faster repeated read setup, at the cost of more write CPU and stored metadata. Buffered snapshots also persist synthesized Parquet pages.

Both modes can read persisted layouts, including after reopen. Changing modes applies to later writes; it does not backfill older snapshots.

WHAT YOU PAY FOR THIS

History takes space. Compatibility sets the boundaries.

No garbage collection or compaction: old pages remain stored. Rewritten pages use PLAIN encoding. No emitted bloom filters. UPDATE assignments take literals only; nested assignments are limited to NULL on optional columns. Predicate pruning is conservative, not a guarantee that a page contains a match.
